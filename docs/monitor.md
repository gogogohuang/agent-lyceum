# Monitor mod (Claude Code)

`plugins/status-monitor` is a Claude Code **mod**, not an ordinary plugin: it is written against Claude Code's mod hooks API (`import type { Register } from 'claude-code'`) and runs inside the Claude Code session, where it adds toasts and a `/status-monitor` pane fed by `agent-lyceum status --json --watch`, one long-running process that prints a line only when a run's files change (no polling). It needs a Claude Code build that supports mods; it does not change how agent-lyceum itself runs. It shows live run status for one or several projects.

**Load it.** Build first (`npm run build`; the mod runs `dist/cli.js`), then start a session with:

```
claude --plugin-dir /path/to/agent-lyceum/plugins/status-monitor
```

`--plugin-dir` only applies when a session starts; an already-open session must be restarted (`claude --resume --plugin-dir ...` keeps the conversation). To load it every time, add `alias claude='claude --plugin-dir /path/to/agent-lyceum/plugins/status-monitor'` to your shell rc, or, for hosts where you cannot pass a flag (desktop app, SDK), set `CLAUDE_CODE_PLUGIN_DIRS` to the mod folder. While a session is running, saving a file in the mod folder hot-reloads it.

**Use it.**
- **Toasts:** a message pops up when a run finishes, is interrupted, or an agent's wake fails (prefixed `[project]` when several are watched). Nothing to do.
- **`/status-monitor`:** type it to open (or, if already open, close) the pane. It is off at session start unless `autoOpen` is set. In the **fullscreen layout** (`"tui": "fullscreen"` in `~/.claude/settings.json`, restart the session to apply; `/tui fullscreen` does the same) from 110 terminal columns it docks on the right at half the terminal width (drag it to any width), and tabs and **關閉** (Close) can be clicked. Otherwise it shows above the prompt; the layout is fixed when the session starts, so a session started on the main screen stays that way. Keyboard (works in both): `x` closes, `v` switches graph/text, `e` expands or collapses the details, `1`-`9` or Tab/Enter switch task, Esc returns to the prompt, running the command again also closes. It draws the agents as a tree: the lead on top and a branch to each member, **each agent in its own rounded frame** whose colour is its state (green working, yellow queued, red last wake failed, gray idle). The branch glyph sits outside the frame, beside its top edge, and says who may write to whom from `can_message` (`▼` the lead may write to the member, `▲` the member to the lead, `↕` both, `─` neither; yellow marks the latest hand-off); a bar runs down the left of a frame that has another member below it. Members are ordered by who needs a look first: working, failed, queued, then idle. When an agent's last wake failed, a red line at the top of the tree names it. Collapsed, a frame is one title line with the state (the round and elapsed time while working, the count while queued, `備援中` on a backup model), and three or more idle members share one line, `另有 N 個閒置：…`. Mail is shown as one key line each: the point of the mail by type (task: the goal; reply: the changes; done: the result), plus any open item, risk or unfinished part it reports (none when it says None) — not the start of the text cut short. Press `e` to expand: every section of every mail (task: goal and acceptance criteria; reply: changes, verification, open items, risks; done: result and what is not done), the wake count and output tokens with a bar relative to the busiest agent, a "→" line of the agents it may message (the latest hand-off marked "●"), and the full checklist; collapsed, the checklist is only the progress bar and the current step. Text wraps inside its frame instead of being cut. Above the tree: the run id and state, output and cache tokens, the task (always one line, ending in `…` when it is too long), progress bar and checklist; below it: blocked integrations, notes and the result summary. `v` switches to the plain text list (per-runtime tokens, per-agent statistics, the last 8 wakes). Each task that is not finished (completed or partial) is a tab, newest first, its title filling the rest of the line (ending in `…` when cut; with several projects it is prefixed by the project name, up to 20 cells): running ones, and also interrupted, waiting-for-answers and ended blocked, failed or cancelled ones, marked with their state in the tab title. A task leaves the pane when it ends completed or partial (or you `clear` it); interrupted, waiting and ended blocked, failed or cancelled ones stay. It updates the moment the run's files change.
- **`/status-monitor band`:** shows the same status as a band above the prompt at the full terminal width instead of the docked pane (type it again to hide it; `/status-monitor` goes back to the pane). Same content, same keys.

**Configure it.** In `~/.claude/settings.json` under `pluginConfigs."status-monitor@inline"` (`options`):

| Option | Meaning | Default |
|---|---|---|
| `command` | CLI to run, split on spaces, e.g. `node /path/to/agent-lyceum/dist/cli.js` | `agent-lyceum` |
| `project` | Registered project name(s) (`-p`); comma-separate to watch several; empty infers from the session's directory | empty |
| `intervalSeconds` | Only used if `status --watch` cannot be started (an older CLI): then status is polled this often | `1` |
| `maxColumns` | Upper bound for the pane's opening width (half the terminal) and the width the tree is drawn at | `250` |
| `autoOpen` | Open the pane when a session starts (it seats only from 144 columns when opened unasked) | `false` |

Changes take effect on the next session start. If the pane shows `無法取得狀態：...`, the `command` could not run (usually `dist/cli.js` was not built) or the project name is not registered.

**Fallback badge.** When an agent that has a fallback chain is running on a backup model, its block title carries a small `備援中` (on a fallback) mark; nothing else in the layout changes. Which model it fell back from and why, and any cooldown, are in `agent-lyceum status`.

**Cache usage.** The run line also shows the prompt-cache input tokens read and written over the run and the share that was read (`快取 讀 … 寫 … 命中 …%`), the same as `agent-lyceum status`. It is recorded for `claude` agents only; runs from before this was recorded, and codex agents, show nothing.

**How it stays current.** The mod starts `agent-lyceum status --json --watch` once per watched project. It watches the project's `runs/` directory (debounced 100 ms, since a round writes several files) and prints one JSON line (the project report plus one report per task that is not finished, i.e. neither completed nor partial) when the result differs from the last line; a task that just finished is included once more so the toast can fire. `--heartbeat <sec>` (default 5) is the slow re-check for what a file event cannot show (a dead lock holder, a `runs/` directory that did not exist yet). The process ends when its parent goes away. If it cannot run, the mod logs why to the debug log and falls back to polling at `intervalSeconds`.

**Parallel instances.** When a member runs as several instances (see [Parallel instances of one member](how-it-works.md#parallel-instances-of-one-member)), each instance is its own block in the tree, sorted together with all member blocks by state (working, failed, waiting, idle), not placed next to its member, and shows its state like any agent. An instance 2 or higher is titled `frontend #2`; instance 1 keeps the member's name. Tasks waiting for an instance are queue items marked `held`, shown under the member's name. Grouping instances under their member in the tree is not built yet; the text pages show `role #k` only for real instances, not for a configured agent whose name merely ends in `--k`. These fields (`role`, `instance`, `held`, `instances` in each run report of `status --json`; `role` and `instance` are on the agent rows of a member that has instances, `held` on its waiting queue items) exist only once a run has used instances; other runs print what they did before. The text pages show an instance 2 or higher as `role #k` and mark held mail "（保留中，等待空閒實例）". (`src/status.ts`, `plugins/status-monitor/hooks/graph.ts`)
