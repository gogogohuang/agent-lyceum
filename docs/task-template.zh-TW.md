# 任務檔範本

複製成 `spec.md` 填寫後，執行 `agent-lyceum run --task-file spec.md`。任務一開始就寫清楚範圍、驗收條件與驗證指令，lead 才能把獨立工作一次派齊，並在小修改時略過 QA 層（見 [節省 token](configuration.zh-TW.md#節省-token)）。沒有驗收條件或驗證指令章節的任務檔會收到警告（仍會執行）。括號內是提示，填完請刪除。

```markdown
# <一行標題>

## 範圍
（要改什麼、為什麼，幾句話即可。列出預期會動到的檔案或模組；lead 靠它判斷哪些可以平行。）

## 驗收條件
- `npm test`
- src/web/feature.txt

## 不可動的範圍
（不得變動的檔案、模組或行為。）

## 驗證指令
- `npm test`

## 若被卡住
（停下來，回信列出已嘗試的做法，不要猜。）

## 需要核准
（需要使用者先同意的動作，例如動到正式環境。）

## 是否小修改
（是／否。只有「數行、有修前失敗／修後通過的測試、不改變使用者可見行為」才答是；答是且 code review 通過時，lead 可略過 QA。）
```

驗收整行只有 `None`、`` `None` ``、`as stated` 或 `同上` 會被退回。`verify.bind_task` 只抽出兩種寫法：整條 bullet 就是該指令，或該行位在以三個反引號開頭的區塊裡（開頭那一行可以再加語言名，例如 bash）。句子裡夾著的反引號不算。區塊的樣子是：`## Verification` 底下，一行只有三個反引號，接著指令，再一行只有三個反引號。例如中間那一行是：

    npm run typecheck
